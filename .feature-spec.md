# Feature: Time-of-day greeting in the welcome message

GitHub Issue: https://github.com/joebew42/ex_chat/issues/28

## Summary

When a user joins a chat room they currently receive a static welcome message:

> `welcome to the <room> chat room, <user>!`

We want to extend this so the message is prefixed with a greeting that depends
on the time of the day. For example, a user joining in the morning should be
greeted with something like:

> `Good morning, Joe! Welcome to the default chat room, Joe!`

## Current behaviour

- `ExChat.UseCases.JoinChatRoom.on/2` builds the message
  `"welcome to the #{room} chat room, #{user_id}!"` and notifies the user via
  `UserSessions.notify/2` (`lib/ex_chat/use_cases/join_chat_room.ex:8`).
- The message is asserted in `join_chat_room_test.exs` (unit) and in
  `websocket_acceptance_test.exs` (acceptance).

## Desired behaviour

On a successful join, the notified message must open with a time-of-day
greeting addressed to the user, followed by the existing welcome text.

### Greeting buckets (local server time)

| Time range            | Greeting        |
| --------------------- | --------------- |
| 05:00 – 11:59         | `Good morning`  |
| 12:00 – 16:59         | `Good afternoon`|
| 17:00 – 20:59         | `Good evening`  |
| 21:00 – 04:59         | `Good night`    |

### Message format

```
<greeting>, <user_id>! Welcome to the <room> chat room, <user_id>!
```

Example (morning): `Good morning, a-user! Welcome to the default chat room, a-user!`

## Design / plan

1. **Add a greeting module** — introduce `ExChat.Greeting` (`lib/ex_chat/greeting.ex`)
   with a pure function `greeting/1` that maps a `Time`/hour to one of the four
   greeting strings. Keeping the time-to-greeting mapping in its own pure module
   makes it trivially unit-testable and keeps the use case thin.
2. **Make the clock injectable** — allow the current time to be provided so tests
   are deterministic. Default to the real clock (e.g. `Time.utc_now/0`) in
   production, and let `JoinChatRoom` obtain the greeting for "now".
3. **Wire it into `JoinChatRoom.on/2`** — build the message as
   `"#{greeting}, #{user_id}! Welcome to the #{room} chat room, #{user_id}!"`
   before calling `UserSessions.notify/2`.
4. **Update tests** —
   - Add unit tests for `ExChat.Greeting` covering each time bucket and its
     boundaries.
   - Update `join_chat_room_test.exs` to assert the new message shape (the
     greeting portion is time-dependent, so assert the composed message given a
     fixed/injected time, or assert it contains the welcome suffix).
   - Update `websocket_acceptance_test.exs` welcome-message assertions to match
     the new format.

## Acceptance criteria

- [ ] A user joining a room receives a message prefixed with the correct
      time-of-day greeting for the current server time.
- [ ] Greeting selection follows the buckets in the table above, including the
      boundary hours.
- [ ] The existing "welcome to the <room> chat room, <user>!" text is preserved
      after the greeting.
- [ ] The greeting logic lives in a pure, independently unit-tested module.
- [ ] All existing and new tests pass.

## Out of scope

- Per-user timezone handling (greeting is based on server time).
- Localisation / translation of greetings.

## Progress

- [x] `ExChat.Greeting` module with pure `greeting/1` mapping a `Time` to one of the
      four greeting strings, covered by unit tests for each bucket and its boundaries.
- [x] `JoinChatRoom.on/3` accepts an injectable `now` (defaulting to `Time.utc_now/0`),
      composes the message `"<greeting>, <user>! Welcome to the <room> chat room, <user>!"`,
      and its unit test asserts the composed message with a fixed injected time.
- [x] `websocket_acceptance_test.exs` welcome-message assertions updated to the new
      format via a `welcome_message/2` helper that derives the expected greeting from
      `Time.utc_now/0` (matching the real clock used in the acceptance flow).
- [x] All 54 tests pass.

### Key decisions

- Night bucket (21:00–04:59) is expressed as two guard clauses (`21..23` and `0..4`)
  since `Time` hours don't wrap; behaviour matches the spec table.
- The acceptance test derives the greeting from the live clock rather than injecting
  time, because the WebSocket flow uses the production `Time.utc_now/0`. A greeting
  computed at production time and re-computed at assertion time could in theory differ
  only if they straddle an exact bucket boundary — an accepted, negligible edge for an
  acceptance test.
