# Feature: Chat command `/who`

GitHub Issue: https://github.com/joebew42/ex_chat/issues/30

## Summary

Support a new chat system command `/who`. When a user sends `/who` in the chat,
the server replies back to that user with their information. As a first
implementation, the response contains the user's name.

Request:

```
/who
```

Response:

```
"You are logged in as Joe"
```

## Context

In the current architecture the `session_id` that flows through the websocket
layer **is** the username:

- `ExChat.UseCases.CreateUser` calls `UserSessions.create(username)` and
  `AccessTokenRepository.add(access_token, username)`.
- `ExChat.UseCases.ValidateAccessToken` returns that username as the
  `user_session`, which `WebSocketController` keeps as its `session_id`.

Therefore `/who` can be answered directly from the sender's `session_id`
without any new lookup — the "user name" is the `session_id`.

The frontend (`priv/static/chat.html`) has no slash-command parsing; users type
free text into the message input and it is sent as
`{"room": <room>, "message": <text>}`. Consequently `/who` arrives as an
ordinary chat message whose content is exactly `/who`. The server intercepts
that message and answers **only the sender** (it is not broadcast to the room).

## Acceptance Criteria

- When a connected user sends a chat message whose content is `/who`, the server
  replies to that user with `You are logged in as <username>`.
- The `/who` response is delivered only to the sender, not broadcast to the room
  or to other users.
- A normal chat message that merely contains `/who` as part of a longer text
  (e.g. `who is there /who`) is still treated as a normal message and broadcast
  as usual. Only a message whose full content is `/who` triggers the command.

## Design

- Response shape follows the existing system-message convention (JSON replied
  directly on the socket): `{"message": "You are logged in as <username>"}`.
- Introduce a use case seam `ExChat.UseCases.WhoAmI` that, given the user's
  `session_id`, returns `{:ok, "You are logged in as <username>"}`. This keeps
  the controller thin and matches the existing `UseCases` structure, and leaves
  room to return richer user information later.
- Add a `handle/2` clause in `WebSocketController` that pattern-matches a
  message with content `"/who"` and replies directly to the sender. The clause
  must be placed **before** the generic `%{"room" => room, "message" => message}`
  clause so the command is intercepted before it is broadcast.

## Implementation Plan (TDD, inside-out)

1. **Use case** — `ExChat.UseCases.WhoAmI`
   - Add `test/ex_chat/use_cases/who_am_i_test.exs`: `WhoAmI.on("a-user")`
     returns `{:ok, "You are logged in as a-user"}`.
   - Implement `lib/ex_chat/use_cases/who_am_i.ex`.

2. **WebSocket controller** — intercept `/who`
   - Add a `handle/2` clause matching `%{"message" => "/who"}` that calls
     `WhoAmI.on(session_id)` and replies `{:reply, {:text, to_json(%{message: ...})}, session_id}`.
   - Place it before the generic message clause.

3. **Acceptance test** — `test/ex_chat/web/websocket_acceptance_test.exs`
   - Add a describe block "As a User when I send the /who command":
     - sending `{"room":"default","message":"/who"}` results in
       `assert_receive "{\"message\":\"You are logged in as a-user\"}"`.

- The exact string match `"message" => "/who"` (not a substring/regex) is what
